# 手动验收脚本（发布后）

假设：

- 站点地址：`https://i.example.com`
- 管理员账号可正常登录
- 已准备一个测试用户与一个测试文件

## 1. 基础可用性

1. 打开首页与登录页，确认可进入 OAuth 登录流程。  
2. 打开 `GET /api/system/forbidden-image`，应返回 200 且可显示禁止访问图。  
3. 登录后访问控制台，确认文件列表与视频列表可正常加载。  

## 2. 上传与预览

1. 上传 1 个图片文件与 1 个文本文件。  
2. 确认上传完成后可复制直链，预览正常。  

## 3. 封禁与申诉闭环

1. 使用管理员进入“全局文件”页面，对测试文件执行“封禁”，填写理由。  
2. 用户侧刷新文件列表，应看到“已封禁”状态和封禁原因。  
3. 用户访问该文件直链，确认被重定向到禁止访问图。  
4. 用户在文件页面提交申诉工单（填写理由）。  
5. 管理员进入“申诉工单”页面，执行两种测试：
   - 路径 A：通过申诉 -> 文件恢复可访问
   - 路径 B：彻底删除 -> 文件被删除且不可恢复

## 4. 审计日志核验

在管理员“审计日志”页面确认至少出现以下动作：

- `file_banned`
- `file_appeal_submitted`
- `file_appeal_approved` 或 `file_appeal_deleted`

## 5. 回归检查

1. 普通文件上传、分享、回收站恢复功能无回归。  
2. 管理员用户配额调整功能正常。  
3. 服务日志无持续错误（`journalctl -u ideasaver -f` 观察 5-10 分钟）。
